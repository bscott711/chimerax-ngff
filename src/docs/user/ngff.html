Opening OME-Zarr (OME-NGFF) images

The ChimeraX-NGFF bundle opens local OME-Zarr stores (folders named *.zarr, usually *.ome.zarr) as volume data: 

open path/image.ome.zarr

File > Open Folder... (format “OME-Zarr (OME-NGFF) image”) and dragging the folder onto the ChimeraX window work as well. The format name is OME-Zarr (NGFF) and its nickname is ngff: open path format ngff forces it, which is needed for a folder name that does not end in .zarr or that ends in /.

Option:

  • series name – open this series group of a bioformats2raw store (for example series 1) instead of the image the store describes at its root.

Time points become a volume series (play them with the slider or the vseries command) and channels become separate coloured volumes, using the OMERO colours when the store has them (otherwise green, magenta, cyan, yellow, then gray). Lower resolution levels are read automatically whenever ChimeraX shows the data at a coarser step, so large images open quickly; they open showing the whole volume at a coarse step, and volume #1 step 1 shows full resolution. Voxel sizes are used in the units the store gives (for example micrometres), as for OME-TIFF.

Environment variables: CHIMERAX_NGFF_CACHE_MB sets the decoded-chunk cache (default 1024 MB, 0 disables it); CHIMERAX_NGFF_LEVELS=omero uses each channel's OMERO window as its initial image levels instead of ChimeraX's automatic levels.

Supported: zarr v2 and v3 (including sharding), OME-NGFF 0.1 to 0.5, bioformats2raw layouts, and plain zarr arrays. Not supported in this version: remote stores (http, s3), labels, HCS plates, and restoring these volumes from ChimeraX sessions.
